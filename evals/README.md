# Evals

One runner and one result format for every xr-ai eval. Cases are YAML, the model stack is chosen with
`--profile`, and results are JSONL. The contracts are in `evals/EVAL_SCHEMA.md` (cases and results) and
`app-sdk/xr-ai-app/docs/PROFILES_SCHEMA.md` (profiles).

```text
evals/
  runner/      xr-ai-eval: package xr_ai_eval and the `xr-ai-eval` command
  adapters/    xr-ai-eval-adapters (experimental): run the existing harnesses and convert their output
  <suite>/     cases/*.yaml and fixtures/ for a suite (filled by later work packages)
  results/     default output of `run` (not committed)
  baselines/   <suite>.<profile>.jsonl, same schema
```

Install with `uv --config-file uv.toml sync --project tests` (the tests project lists it), or
`uv --config-file uv.toml pip install -e evals/runner -e evals/adapters`.

## Run a suite

```bash
xr-ai-eval run --suite tea_visual --evals-dir evals/suites --profile local --out results.jsonl
xr-ai-eval run --suite tea_visual --evals-dir evals/suites --profile hybrid --tags visual --roles perceive
```

`--suite` is a directory under `evals/` with `cases/*.yaml`, or the name of an installed adapter (below).
`--profile` is a path, or a name found as `models.<name>.json|yaml|yml` in `--profiles-dir`, the current
directory or `evals/profiles/`. Each case calls the endpoint that fills its role (the profile's `roles` map,
then an entry of that name, then the legacy alias such as `vlm` for `perceive`) through
`/v1/chat/completions` with temperature 0. Results append to `--out`, default
`evals/results/<UTC date>-<commit>.jsonl`.

Exit code: 0 when every executed case passed, 1 when any failed or errored, 2 for invalid cases, profiles
or result files. A case that errors still writes one record with `pass: false`; a case with `skip_reason`
writes none.

Each record has latency (wall time of the model call), `tokens` (`null` when the endpoint omits `usage`),
`gpu_profile` from the profile, and `gpu_memory_mb`, the host-wide used GPU memory in MiB from `nvidia-smi`
right after the call (omitted when `nvidia-smi` is missing; `--no-gpu-memory` skips it). Because it is
host-wide, it includes other processes on the GPU.

Scorers: `exact`, `contains`, `regex`, `choice`, `json_match` (partial score per field), `python` (`function: "file.py:fn"`, called as `fn(case, result)`) and `judge`
(`scorer: {type: judge, role: decide, rubric: ...}`; the judge's role and preset go in `detail`).
Cases may set `system`, `input.turns` (multi-turn), `input.audio` (a transcription call to the `speech_in`
endpoint) and `input.driver` (`file.py:fn(endpoint, case) -> str`, for transports the runner does not
speak) with `input.params` for the hook. Hook files are loaded by path relative to the case file. See `evals/EVAL_SCHEMA.md`.
Suites under `evals/suites/` (tea visual, speech, `xr_render_scenes`) run with `--evals-dir evals/suites`. `xr_render_scenes` runs the xr-render supervisor over the original harness's in-memory scene (69 cases generated by `generate_cases.py`); it needs `xr_render_demo_eval` importable and only the `answer` role is a real model.

Python scorers and drivers run arbitrary code with your privileges: run only trusted suites. Hook files must
lie inside the suite directory (paths that resolve outside it are rejected). Cases skipped through
`skip_reason` (for example recorded media not captured yet) write no record, so they do not appear in
`report` or the scorecard; count them from the case files.

## Matrix and scorecard

```bash
xr-ai-eval matrix --suite tea_visual --suite conversation-context --evals-dir evals/suites \
    --profiles local,hybrid --presets cosmos3_nano_reasoner,nemotron_omni --out matrix.jsonl
xr-ai-eval report --results matrix.jsonl --out scorecard.md
```

`matrix` runs every suite against every profile; with `--presets` it also requests each preset as the model
name in place of the profile's own (the endpoint stays the profile's). `report` writes one row per
`(suite, role, model)` with pass rate, errors and the median of latency, input tokens, output tokens and GPU
memory over records without an error. Output is deterministic.

## Existing harnesses (experimental)

**Experimental.** The adapter parsers follow each harness's source and are tested on fixtures built from its format strings, not on live recordings. The `uv run --project` commands are unverified for most harnesses (no live run has recorded their real output yet). Treat adapter scores as indicative until a harness emits JSONL itself.

Adapters run a harness as a subprocess in its own project environment and convert what it printed or
wrote. The harnesses are not changed.

| Suite name | Harness | Reads | Takes `--profile`? |
| --- | --- | --- | --- |
| `tea-making` | `agent-samples/tea-making-sample/eval/eval.py` | printed lines | no, uses `yaml/models.json` |
| `lab-instrument-monitoring` | `eval/eval.py`, `eval/visual_eval.py` | printed lines | no, uses `yaml/models.json` |
| `conversation-example` | `eval/run_decision_eval.py` | `--output` JSONL | no, uses `yaml/models.json` |
| `conversation-context` | `xr-ai-conversation/eval/conflict_eval.py`, `compaction_eval.py` | printed lines | yes (`--models`, `--model`) |
| `xr-render-demo` | `xr_render_demo_eval.harness` | printed lines | no |
| `procedure-capture-guide` | `evaluate_visual_checks.py`, `evaluate_captions.py` | `results.jsonl`, per-case JSON | visual checks only (`--models`) |

The recorded `profile` is the one the harness really used: the requested profile when the harness takes
it, otherwise `sample-models` with `detail.requested_profile` and `detail.profile_honored: false`.
Latency is the harness's own `latency_s` when it reports one; otherwise the gap between result lines
(`detail.latency_basis: gap_between_output_lines`), or the run average when nothing was timed. Token counts
are `null`. Cases a harness's YAML lists but that never reported become error records. A non-zero harness
exit after it reported cases means "finished with failures"; with no cases it becomes one error record.
`evaluate_recorded_packet.py` needs a recorded packet and guide as input and is not adapted.
